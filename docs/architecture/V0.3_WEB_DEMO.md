# V0.3 Web Demo Architecture / V0.3 网页演示架构

```text
Browser (cloudcore.moyee.uk)
  └─ Cloudflare Worker
       ├─ React/Vite static assets
       └─ Python Worker → FastAPI → existing Python Core → Azure Responses API
```

One Cloudflare Worker serves both the website and Python API. There is no external API host, authentication, task registry, database, or durable filesystem dependency. / 同一个 Cloudflare Worker 同时提供网站和 Python API。不依赖外部 API 主机，不设置登录、任务注册表、数据库或持久文件系统。

## Stateless request lifecycle / 无状态请求流程

1. `/api/demo` reads the bundled synthetic CSV from Static Assets; loading the page makes no model request. / `/api/demo` 从静态资源读取捆绑模拟 CSV；页面加载不调用模型。
2. `/api/upload/validate` validates an uploaded CSV in memory, without cleaning or rewriting it. / `/api/upload/validate` 在内存中校验上传 CSV，不清洗或改写源数据。
3. User click on **Run AI Analysis** sends either the bundled CSV or the selected file to `/api/analyze`. The API validates again, applies Python Offer/Reason and analysis, and submits only allowlisted message-generation fields to Azure in configured batches. / 用户点击 **Run AI Analysis** 后，捆绑 CSV 或选中文件才会发至 `/api/analyze`。API 再次校验，使用 Python 生成 Offer/Reason 与分析，并按配置分批向 Azure 提交允许的文案字段。
4. Python validates each returned Message, builds the exact seven-column CSV in memory, and returns results and token totals. The browser holds results in memory and downloads the CSV locally. No upload, result, or partial batch is retained by the app. / Python 校验 Message，在内存中生成严格七列 CSV，并返回结果和 Token 总量。浏览器仅在内存中暂存并由用户下载；应用不保存上传、结果或部分批次。

## Runtime and data scope / 运行与数据范围

- Python owns input validation, Playbook O1–O4, Offer/Reason, internal MRR × Churn Score analysis, batching and message validation. The model generates Message only. / 输入校验、O1–O4、Offer/Reason、MRR × Churn Score 内部分析、分批及文案校验均由 Python 执行；模型只生成 Message。
- Input schema `support_tier` accepts the configured values `Basic`, `Standard`, `Premium`, and `Enterprise`; matching is case-insensitive and trims surrounding whitespace without rewriting source values. Only Basic selects O1; all other tiers use the same MRR and Tenure rules. / 输入 Schema 的 `support_tier` 有效值为 `Basic`、`Standard`、`Premium`、`Enterprise`；校验忽略大小写和首尾空格，但不改写源值。仅 Basic 触发 O1；其余等级使用相同的 MRR 和 Tenure 规则。
- Cloudflare Worker Secret `AZURE_OPENAI_API_KEY` supplies the API key. It is never included in static assets, source, or browser data. / Cloudflare Worker Secret `AZURE_OPENAI_API_KEY` 提供 API Key，不进入静态资源、源代码或浏览器数据。
- The page initially displays the bundled synthetic CSV. Any uploaded CSV that passes the same input schema validation is eligible for analysis after the user clicks **Run AI Analysis**; this is the user's authorization boundary for sending the approved message-generation fields to Azure. / 页面初始显示捆绑模拟 CSV。任何通过相同输入 Schema 校验的上传 CSV，在用户点击 **Run AI Analysis** 后均可进入分析；点击操作作为用户将获准的文案生成字段发送至 Azure 的授权边界。
- Azure receives only the existing allowlist: industry, products, tenure, support tier, selected offer code and batch-local IDs. Customer ID, region, MRR and churn score remain local; Python still calculates Offer, Reason and the internal index. / Azure 仍只接收既有允许字段：行业、产品、Tenure、Support Tier、选定 Offer 代码和批次内 ID。客户 ID、地区、MRR 和 Churn Score 保留在本地；Offer、Reason 和内部指数仍由 Python 计算。
- The public demo has no login. Anyone who can access it can submit a schema-valid CSV and trigger processing by clicking the analysis button. / 演示站不设登录。任何可访问网站的人都可以提交符合 Schema 的 CSV，并通过点击分析按钮触发处理。
- Each request is synchronous and stateless. A failed request has to be submitted again; successful records from a partial response are not retained. / 请求同步且无状态；请求失败需重新提交，不保留部分成功记录。

## Cloudflare config / Cloudflare 配置

The repository root `wrangler.jsonc` points to `backend/worker.py`, enables `python_workers`, serves `web/dist`, and binds only `cloudcore.moyee.uk/*` under the `moyee.uk` zone. A Wrangler pre-bundle script copies the existing Python core into Pywrangler's generated modules directory. The apex personal-site route is not modified. Workers Builds root is `.`; build and deploy commands are in the root README. / 根目录 `wrangler.jsonc` 指向 `backend/worker.py`，启用 `python_workers`，托管 `web/dist`，并只绑定 `moyee.uk` 区域下 `cloudcore.moyee.uk/*`。Wrangler 打包前脚本会将现有 Python 核心复制到 Pywrangler 生成的模块目录。不修改个人主站 apex 路由。Workers Builds 根目录为 `.`；构建和部署命令见根 README。
