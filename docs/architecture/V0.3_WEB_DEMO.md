# V0.3 Web Demo Architecture / V0.3 Web Demo 架构

## Topology / 部署拓扑

```text
Browser (cloudcore.moyee.uk)
  └─ Cloudflare Worker: React + TypeScript + Vite Static Assets
       └─ /api/* → Worker reverse proxy → standalone FastAPI container
                                            ├─ existing Python Core + Azure Provider Adapter
                                            └─ persistent disk: SQLite, source, checkpoints, results
```

Cloudflare Python Workers support FastAPI, but the current backend requires persistent SQLite and per-task filesystem artifacts for task state, uploads, checkpoints and results. Worker-local files cannot provide durable state across instances/restarts. Moving state to Cloudflare storage requires a broader backend redesign, so the existing FastAPI Docker service remains the API host on a persistent disk. The Worker serves static assets and proxies `/api/*`; TypeScript does not implement customer business logic. / Cloudflare Python Workers 技术上支持 FastAPI，但当前后端要求持久 SQLite 和逐任务文件，用于保存任务状态、上传文件、检查点及结果。Worker 本地文件无法跨实例/重启提供持久状态。迁移至 Cloudflare 存储需要更大范围后端重构，因此现有 FastAPI Docker 服务继续运行于持久盘。Worker 负责静态资源和 `/api/*` 代理；TypeScript 不实现客户业务逻辑。

## Request and data boundaries / 请求与数据边界

- `/api/demo` serves the bundled 45-row synthetic CSV; page load never starts model work. / `/api/demo` 返回随项目提供的 45 行模拟 CSV；页面加载不会启动模型调用。
- Python validates uploaded CSV read-only. Azure calls default to the bundled synthetic data; uploaded calls remain server-side opt-in. / Python 只读校验上传 CSV。Azure 默认只处理捆绑模拟数据；上传文件模型调用由服务端控制。
- Azure key, access code and session signing secret remain server Secrets on the FastAPI host. The Worker only needs the non-secret `BACKEND_ORIGIN`. / Azure key、访问码和 Cookie 签名密钥仅作为 FastAPI 主机的服务端 Secret。Worker 只需非敏感 `BACKEND_ORIGIN`。
- The existing `run_live()` owns Offer/Reason, internal analysis, batching, Message validation, checkpointing, retry and seven-column export. Task files live on the API host's persistent disk. / 现有 `run_live()` 负责 Offer/Reason、内部分析、分批、Message 校验、检查点、重试及七列输出；任务文件保存在 API 主机持久盘。

## Deployment boundaries / 部署边界

The Worker configuration lives in `web/wrangler.jsonc` because Workers Builds Root directory is `web`. Its only custom route is `cloudcore.moyee.uk/*` in `moyee.uk`; the apex personal site is not routed or modified. The API service stays separate. / Worker 配置位于 `web/wrangler.jsonc`，Workers Builds Root directory 应为 `web`。唯一自定义路由是 `moyee.uk` 区域下的 `cloudcore.moyee.uk/*`；不会路由或修改个人主站 apex 域名。API 服务保持独立。

## Limits / 限制

This is a lightweight shared-access demo, not production SaaS. Shared access has no per-person identity or audit attribution. Task records and customer-level outputs remain on persistent storage until manually removed under the approved retention schedule. / 这是轻量共享访问演示，不是生产 SaaS。共享访问码无法区分个人身份或记录个人审计归属。任务记录和客户级输出保存在持久存储中，需按批准的保留计划手动删除。
